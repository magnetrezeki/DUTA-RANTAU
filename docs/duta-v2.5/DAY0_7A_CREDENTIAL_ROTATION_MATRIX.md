## Dependency conclusions

- Normal browser operation needs `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- Server cookie handling and the proxy use the same public Supabase configuration. `NEXT_PUBLIC_*` use is intentional for endpoint and publishable key; no repository evidence shows a server secret under a `NEXT_PUBLIC_*` name.
- `SUPABASE_SECRET_KEY` is server-only and optional for the admin audit/account-deletion path. Normal application authentication, Preview bootstrapping, and the authenticated RLS harness do not require a service role.
- `APP_DATABASE_URL` and `SYSTEM_DATABASE_URL` are server-only restricted database paths. Six integration tests require `APP_DATABASE_URL`; the suitable target is an isolated local test database, never production.
- `DATABASE_URL` is a Drizzle/tooling input and deliberately is not used as the application runtime fallback. `DIRECT_URL` is legacy/tooling documentation only.
