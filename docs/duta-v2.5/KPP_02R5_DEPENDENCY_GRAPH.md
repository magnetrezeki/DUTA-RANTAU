# KPP-02R.5 Dependency Graph

```text
W0 legal/source/privacy/Shariah decisions
 ├─ W1 public access + free Member + IA
 │   ├─ W2 trusted source health/verification/pipeline/distribution
 │   │   └─ W3 Hari Ini + Tanya + Info Rantau
 │   ├─ W4 Member continuity/preferences/lifecycle
 │   ├─ W5 Rantau/Community/Organization
 │   └─ W6 Kerja/Pasar/Map
 └─ W7 Control Center/moderation/privacy/security
     ├─ W5 Community UGC
     ├─ W6 Pasar complaint/revocation
     └─ W9 release verification

W8 secondary: DUTA Belajar depends on content authority; visual-anchor manifest
depends on Founder rights approval. DUTA Photo/Points remain deferred.
All completed wave evidence → W9 verification and release evidence pack.

Support chain: Saya support entry → shared scoped case foundation → Support RBAC
and audit → problem/contact/feedback/case-status flows → contextual routing,
notifications and privacy-safe diagnostics. Corporate partnership and investor
inquiries use the same scoped foundation but remain separate from Partner,
Seller, Organization and Community authority.
```

Critical chains:

1. Source use permission → source verification → source pipeline → Hari Ini /
   Tanya trusted answer / Info browse.
2. Public access policy + rate limits → bounded public Tanya; provider fallback
   remains an independent operational gate.
3. Scoped RBAC → moderation states → human review/appeal/audit → Community UGC
   and Seller complaint release.
4. Age legal classification → future creator/seller/representative eligibility;
   it does not block public Visitor safety/information access.
5. Pasar legal boundary → seller/listing workflow → public discovery/connect;
   transactions never enter this chain.
